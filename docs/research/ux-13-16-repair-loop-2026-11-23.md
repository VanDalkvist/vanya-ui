# Repair loop 01: UX-13, UX-14, UX-15, QA-16 — 2026-11-23

## User intent and NMT problem

Fix four concrete issues from the [source-based design-system audit](vanya-ui-design-system-audit-2026-11-23.md) as **one PR**. The job is not to add more patterns: it is to make existing controls truthful and the checks repeatable. The old showcase's floating shortcut dock hid the distance slider while all unit tests passed. Roles like `tab` and `menuitemradio` promise keyboard functionality that the implementation did not fully satisfy. A nav item which cannot show the current section cannot help orientation.

**Constraints:** no merge into main, no automatic GitHub Actions, no new deployment of consumers, preserve the author's neutral hover + accent selected policy, keep native URL fragments and the existing visual language. Local browser verification must be independent of GitHub/Cloudflare.

## Sources

- [W3C APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) and [automatic-activation example](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/examples/tabs-automatic/): one tab in keyboard tab order; arrow/Home/End move among enabled tabs, a real `aria-controls` target must exist; auto-activation appropriate when content is already loaded.
- [W3C APG Menu](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/), [Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/): direct focus in composite menu items, arrows, Escape, Tab leaves menu; selected radio state is durable and different from focus.
- [W3C APG Developing Keyboard Interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/): roving tabindex vs aria-activedescendant, moving focus vs tab stops.
- [MDN aria-current](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-current): `location` reflects current in-page location, not merely last clicked link.
- [Playwright Config](https://playwright.dev/docs/test-configuration), [Locator assertions](https://playwright.dev/docs/api/class-locatorassertions): local webServer, real browser interactions, screenshots and traces. This is a test runner, **not** a design methodology.

No code/visual layouts copied from the references; implementation choices below are product-specific.

## Alternative criticism and decisions

### #13 — a segmented control is not automatically a tabs widget

**Rejected:** adding `ArrowRight` to the existing default `role=tab` while pointing to no panel. The UI would still lie to assistive technology. **Selected:** default `semantics="filters"` (native buttons with `aria-pressed`) for in-place choice/filtering. The explicit `semantics="tabs"` is supported only with `TabSegmentItem` containing `tabId` and `panelId`. Full keyboard roving with automatic activation, skipping disabled items and wrapping. Each consuming product must render the real tabpanel with matching `id` and `aria-labelledby` and only activate immediately available panels.

**Compatibility cost:** default behavior is semantically changed for older consumers (native buttons instead of pseudo-tabs). No unnamed breaking change: note this under Unreleased and do not update consumers automatically. For a real tabs consumer, add explicit `semantics="tabs"` and panel links.

### #14 — ThemeToggle is a composite menu, not a button list

**Rejected:** only keeping the existing Arrow/Escape handlers. **Selected:** give all menuitemradio controls `tabIndex=-1`; focus them programmatically on open; add Home/End, ArrowUp/Down, trigger ArrowUp/Down; Tab/Shift+Tab leave to adjacent normal control; blur outside closes; Escape cancels and returns focus to trigger. Expanded, `aria-checked` and selected accent are separate from hover. Keep segment variant as ordinary group.

**Trade-off:** focus-out traversal must only include genuinely tabbable controls, not button tags with `tabIndex=-1`. No global focus trap.

### #15 — viewport and fragments rather than click history

**Rejected:** `onClick => isActive` state that becomes false after manual scroll, Back or direct URL. **Selected:** a single hook derives current section from its position relative to the actual sticky header, throttled with rAF. Native `hashchange`, `popstate` and `pageshow` serve deep links/restore, but **never** rewrite browser history during scroll. The existing `NavLinks` derives `aria-current="location"` for `/#...` URLs.

**Caveat:** nested `#workspace` inside `#catalog` takes precedence when in view. The scroll threshold is a product policy (header bottom + 40px), not a pixel-perfect standard; verify with several real viewports.

### #16 — real browser gate, not another screenshot-only checklist

**Rejected:** more jsdom tests or a permanent, mandatory GitHub Action. **Selected:** optional, manually invoked Playwright 1.65.1 as an isolated subpackage, with a full local production build served through `vite preview` and no cloud credentials. Automated scenarios cover the original slider overlap using real multi-point `document.elementFromPoint` and a synthetic obstruction falsification control, 390/1024/1440 x light/dark, fragments and history, keyboard theme/menu, tabs, drawer Escape, independent scroll owners, press/result, reduced motion and CSS zoom. Screenshots, traces and a report go to ignored local artifacts. Accepted screenshots must be manually reviewed and intentionally committed under `docs/verification/<SHA>/` before labeling UI_VERIFIED.

**Limitations:** source/DOM tests do not certify a11y. Playwright checks do not establish visual attractiveness or screen-reader parity. CSS zoom simulates some zoom geometry; it is not equivalent to manual browser zoom 200%. If the runner cannot execute in the current environment, report `BROWSER_NOT_RUN` and keep this issue open.
