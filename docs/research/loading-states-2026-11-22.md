# Состояния загрузки: исследование для Vanya Arc / UI

Дата: 2026-11-22. Этот документ — самостоятельные выводы для Vanya UI, не перевод и не перепечатка чужой дизайн-системы.

## Источники и проверенные наблюдения

- [Nielsen Norman Group — Skeleton Screens 101](https://www.nngroup.com/articles/skeleton-screens/): skeleton даёт представление о будущем расположении контента и уменьшает ощущение пустого ожидания. Анимация не обязательна и может мешать восприятию. Публичная статья служит основой для общей UX-постановки задачи, а не лицензией на воспроизведение текста или изображений.
- [IBM Carbon — Loading guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/loading/guidelines): для загрузки всего экрана с предсказуемой структурой предлагает skeleton вместо полного loading indicator; для краткого выполнения команды — локальную обратную связь. Не заполнять экран множеством несвязанных спиннеров.
- [Atlassian Design — Skeleton usage](https://atlassian.design/components/skeleton/usage): визуальный placeholder пока данные ещё не пришли, использует общие дизайн-токены. Избыток shimmer может отвлекать; не требуется копировать реализацию Atlassian.
- [MUI — Skeleton](https://mui.com/material-ui/react-skeleton/): примеры текстовой строки, прямоугольника и круга; геометрия определяется будущим содержимым, не случайными анимациями.
- [MDN — aria-busy](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-busy): помечает обновляемую область; для динамических объявлений состояние busy нужно сбрасывать при завершении.
- [GitHub Primer — Loading](https://primer.github.io/design/ui-patterns/loading/): в большой коллекции стоит делать одно объявление загрузки вместо десятков повторяющихся.
- [Evo by eBay — Skeleton Accessibility](https://opensource.ebay.com/evo-web/components/skeleton/accessibility): placeholder не должен получать фокус, переход на реальные данные удаляет skeleton, reduced motion убирает shimmer; один контейнер отвечает за доступное имя.
- [Web.dev — CLS](https://web.dev/articles/cls): заранее резервировать место под будущий контент, чтобы не сдвигать существующие элементы.

## Проектное решение Vanya UI

1. **Известное показываем сразу:** бренд, название раздела и существующая навигация — реальные элементы, а не пустые прямоугольники. Неизвестные результаты — skeleton соответствующей формы.
2. **Место и плотность:** 4–6 правдоподобных карточек в видимой сетке. Для обложек — `MediaCardSkeleton` тех же размеров, что `MediaCard`. Для строки — `Skeleton shape="text"`, для иконок/аватаров — `circle`.
3. **Никаких выдуманных значений:** skeleton не показывает ложный рейтинг, количество людей, прогресс или неподтверждённое завершение. В нём нет активных контролов.
4. **Один статус:** `LoadingRegion label="Загружаем фильмы"` объявляет стадию один раз. Дочерние `Skeleton` скрыты от ассистивных технологий и не попадают в Tab.
5. **Анимация:** спокойная едва заметная пульсация, без перебегающего блика по десяткам карточек; статичный placeholder при `prefers-reduced-motion: reduce`.
6. **Быстрые запросы:** не переключать между разными полноэкранными заставками; если структура уже известна, допускается немедленный shell + skeleton. Для короткого действия (лайк, запись) сохранять контент и давать feedback у действия, а не заменять весь экран.
7. **Ошибка — не загрузка:** запрос с ошибкой/таймаутом заканчивается сообщением с явной следующей командой («Повторить»). Скелетон не может оставаться навечно.
8. **Не прыгать при завершении:** сетка и обложки используют ту же aspect ratio, количество колонок и ширину области, что настоящий каталог. Нельзя вставлять неактивные ссылки и кнопки, изображающие готовый контент.
9. **Проверка:** холодная загрузка с медленным API, ошибка 5xx/таймаут, пустая коллекция, повторный запрос, мобильные 320/390px, десктоп, тёмная тема, reduced motion, keyboard, accessibility tree и отсутствие горизонтального overflow.

## Данные и границы ответственности

Токены `--surface-inset`, `--ink`, `--font-sans`, радиусы и композиция принадлежат Vanya UI и `@vanya/brand`. Компоненты предоставляют **форму**, не знают Film/Movie/URL или серверные схемы. Приложение само выбирает, где рисовать skeleton, что считать ошибкой и какие данные доступны заранее.

## Копирайтинг

- Визуально **не писать** по центру «Открываем…» вместо экрана. Сообщение `label` короткое, в статусе для скринридеров.
- Ошибка: конкретный объект и доступное действие: «Не удалось загрузить фильмы» + «Повторить», без шаблонного «Что-то пошло не так».
- Долгий запрос: «Фильмы загружаются дольше обычного» — только если это уже действительно так, не как регулярный слоган.
- Не использовать слово «пожалуйста», многоточия, якобы мотивирующие описания или технические коды как единственный текст.
- Это собственные формулировки проекта; редакторские первоисточники перечислены в [правилах текстов](../patterns/writing-and-editorial.md), тексты скиллов не копируются.

## Права

Все ссылки — исследовательские источники для решения, сторонние тексты, код и иллюстрации не включены в пакет. Компоненты и примеры здесь созданы самостоятельно с помощью Vanya UI токенов, без заимствования чужого визуального кода.
