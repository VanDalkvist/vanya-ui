# Инспектор сущности: сначала обзор, потом редактирование

**Назначение:** карточка проекта, материала, медиа или записи, открытая в `InspectDrawer`.

Этот паттерн дополняет [композицию рабочих поверхностей](../composition/working-surfaces.md). Он **не вводит новую палитру, шрифт или отдельный компонент**: использует токены, `InspectDrawer`, `ActionButton`, `CategoryBadge` и нативные `details/summary` там, где нужна вторичная область.

## Правила

1. **Главная роль — инспекция**: title, один смысловой summary, существующее состояние, главная ссылка или действие. Повторять summary как редактируемый textarea на первом экране не надо.
2. **Read-only данные не маскировать под настройки**. История, результаты анализа, источник и доказательства — отдельные смысловые блоки с короткими заголовками. Не смешивать метрики с редактированием реестра.
3. **Progressive disclosure**: длинные списки показывают 2–4 первых элемента, потом доступный раскрывающийся блок «Показать остальные N». Прятать всё полезное за неочевидной иконкой запрещено.
4. **Отдельный edit disclosure** «Редактировать карточку». Внутри одного раскрытого блока — поля и кнопки «Отменить»/«Сохранить изменения». Read-mode не содержит постоянно видимой формы, если пользователь пришёл изучить проект.
5. **Сохранение честное**: pending на кнопке, дождаться ответа сервера; на ошибке не закрывать editor. «Отменить» восстанавливает исходное состояние. При закрытии с unsaved — подтверждать потерю данных.
6. **Статус ≠ сегментированная навигация**: не использовать `SegmentedControl` для набора старых lifecycle-меток, если у проекта уже есть реальная модель стадий в другом продукте. Не путать work activity, жизненный цикл и стадию продаж.
7. **Варианты выбора**: `SegmentedControl semantics="filters"` применять только для фильтрации; для выбора категории использовать именованную `role=group` группу кнопок с `aria-pressed` либо семантическое `fieldset`. Если значение может быть пустым, предусмотреть «Нет» / «Без категории».
8. **Семантическая типографика**: основной текст читаемый, идентификаторы/даты — моно, короткие captions. Тексты объясняют последствия управления, а не модель хранения («что произойдёт» вместо «revision increment»).
9. **Один скролл и один владелец фокуса** — используйте встроенное поведение `InspectDrawer`. Не добавлять внутри него второй overflow-y-auto для списка карточек без отдельной причины.
10. **Доказательства и ограничения аналитики**: не называть inferred-classifier tags подтверждённым прогрессом; один event может принадлежать нескольким категориям. Указывать дату и объём рассмотренных событий.

## Смысловой отчёт вместо списка сырых событий

Если пользователь хочет понять, **что изменилось**, а не просмотреть журнал коммитов, основной экран инспектора должен показывать сводку на языке пользователя, сгруппированную по доменным модулям проекта:

- Метрики характера работы — компактно вверху, а не повторять классификацию в каждом пункте.
- 1–3 конкретных вывода об изменениях с **источниками рядом** с утверждением; без нерасшифрованных англоязычных commit messages.
- Основной доменный блок группирует изменения по реально включённым модулям/этапам, не вводит новые категории только ради визуализации.
- Если вывод генеративной модели не подтверждается ссылкой на исходник — **не показывать**. Ссылка доказывает происхождение, не истинность интерпретации.
- Полный список исходных событий — по явному раскрытию, без потери ссылок; не делать его главным содержимым карточки.
- «Следующий шаг» брать из авторитетного состояния проекта, не выдавать модельное предложение за согласованный план.
- Сохранённые отчёты имеют дату. Если продукту нужна **однократная автоматическая первичная проверка**, её можно запускать при первом открытии инспектора после проверки кэша, с явным прогрессом, безопасным продолжением и защитой от дубликатов. Завершённый отчёт не запускается повторно без осознанного обновления. Учитывайте квоты и обработку приватных данных внешним провайдером.

**Пример:** [Ferma semantic project insights](https://github.com/VanDalkvist/ferma/blob/feat/semantic-project-insights/src/components/desk/ProjectInsights.tsx).

## Ровная лента событий внутри инспектора

Для истории коммитов, операций и доказательств используйте **cardless feed** без вложенных карточек:

- Единая сетка: моноширинный идентификатор **фиксированной ширины** / содержание `minmax(0, 1fr)`; внешняя ссылка располагается на стабильном правом краю содержания. Не ставьте иконку вслед за текстом разной длины.
- Заголовок/сообщение — максимум две строки; полный текст доступен через семантическую ссылку и `title`. Минимальная высота двух строк удерживает вертикальный ритм коротких и длинных событий.
- Строка меток имеет зарезервированную высоту; классы операций оформляются как **нейтральные компактные mono tags**, а модуль/домен — как отдельный **accent tag**. Пустая классификация явно обозначается «Метки не определены», а не исчезает бесследно.
- Между событиями — тонкие разделители, единый вертикальный padding. Не создавайте карточку на каждый коммит и не назначайте каждой классификации собственный яркий цвет.
- Длинная история: 2–4 события и раскрытие «Показать ещё N»; у раскрытого состояния должны быть другие текст и направление стрелки. Используйте `details/summary` для клавиатуры, не добавляйте внутренний скролл.
- При узком viewport (включая 320 CSS px) разрешайте перенос **меток**, но не идентификатора или иконки. Не ломайте ширину контейнера на длинных сообщениях (`min-w-0`, `break-words`).
- Проверяйте не только скриншот, но и реальные короткие, длинные, многоклассовые и безметочные события. Разные по длине значения не должны переставлять колонки.

**Реализация-образец:** [Ferma CommitActivityRow](https://github.com/VanDalkvist/ferma/blob/feat/semantic-project-insights/src/components/desk/CommitActivityRow.tsx) — отдельно от политики классификации.

## Проверять перед выпуском

- С первого экрана ясно, **что это за сущность, что изменилось, куда продолжить**.
- Редактирование недоступно без явного действия, но легко находится.
- Нет дублированных значений и конкурирующих верхних navigation/status controls.
- Сохранить, отменить, открыть ссылку, раскрыть подробности, сбросить категорию работают мышью и клавиатурой.
- При 320 CSS px / 200% zoom важные элементы не перекрываются; фокус виден, кнопки подписаны.
- Источники открываются ссылками, error/pending/empty не выглядят как «сломанное приложение».
