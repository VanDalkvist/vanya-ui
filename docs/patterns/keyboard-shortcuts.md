# Горячие клавиши — обязательный паттерн Vanya UI

**Статус:** нормативный документ для всех приложений, использующих Vanya UI. **Аудитория:** дизайнеры, разработчики, LLM-агенты. Публичный источник: https://ui.vanya-arc.dev/reference/keyboard-shortcuts.md. Живые примеры: https://ui.vanya-arc.dev/#keyboard-shortcuts.

## Зачем

Горячая клавиша сокращает путь к **частому** действию. Она не заменяет кнопку, ссылку, меню или понятную подпись. Не назначай клавишу только ради того, чтобы продемонстрировать техническую возможность.

В Vanya UI клавиши — тихий дополнительный слой, который не занимает место в главной навигации. На витрине небольшая кнопка **«Клавиши»** с иконкой клавиатуры в нижнем левом углу открывает существующий `InspectDrawer`; на мобильных экранах остаётся иконка с доступным названием. Подсказки рядом с действиями используют общий компонент `ShortcutKeys` на базе `Kbd`.

## Выбор сочетаний и приоритеты

1. **Сначала системное поведение.** Не переназначай браузерные/OS shortcuts: `Cmd/Ctrl+L` (адрес), `Cmd/Ctrl+R` (обновление), `Cmd/Ctrl+F` (поиск), `Cmd/Ctrl+T/W` (вкладки), `Cmd/Ctrl+C/V/X/Z` (редактирование), `Cmd/Ctrl+P` (печать), `Alt+Left` (назад) и т. п. Полный список зависит от платформы и браузера.
2. **Повторяемые задачи важнее эффектных сочетаний.** Клавиши нужны для поиска, переходов, навигации между списком/редактором и основных команд.
3. **Соблюдай контекст.** Внутри `input`, `textarea`, `select`, `contenteditable`, `role=textbox` буквенные команды не запускаются. При открытом диалоге глобальные команды страницы не работают.
4. **Не ломай клавиатурную доступность.** Сохраняй `Tab`, `Shift+Tab`, `Enter`, `Space`, стрелки и `Escape` с ожидаемым смыслом. Не забирай клавиши у активного контрола.
5. **Одна клавиша без модификатора — исключение.** По WCAG 2.1.4 пользователю должна быть доступна возможность выключить, переназначить или ограничить по фокусу все буквенные/символьные shortcuts. Для схемы `G` → `I` тоже нужен видимый выключатель: последовательность может конфликтовать с голосовым управлением.
6. **Дублируй доступ обычным UI.** Команда перехода должна иметь реальную ссылку `href` или кнопку. Не делай скрытую клавишу единственным способом выполнить действие.
7. **Выбери один словарь команд для приложения.** Не назначай одну последовательность разным действиям в одном scope. Локальные плагины не могут захватывать комбинации родителя.
8. **Не требуй английскую раскладку для ввода текстов.** Обрабатывай `event.key` для символов и осознанно используй `event.code` для физических клавиш, если поддерживаются разные раскладки. Проверь, какой символ показываешь пользователю. `?` всегда продублирован кнопкой в интерфейсе.

## Витрина Vanya UI — работающий пример

| Действие | Команда | Дополнительный путь |
| --- | --- | --- |
| Справка | `?` | Кнопка «Клавиши» внизу слева |
| К первому экрану | `G` → `O` | `/#composition` |
| Айдентика | `G` → `I` | `/#identity` |
| Шрифты | `G` → `T` | `/#typography` |
| Тексты | `G` → `X` | `/#writing` |
| Принципы | `G` → `P` | `/#principles` |
| Компоненты | `G` → `C` | `/#catalog` |
| Рабочие поверхности | `G` → `W` | `/#workspace` |
| Подключение | `G` → `S` | `/#setup` |
| Отмена последовательности, закрыть панель | `Escape` | Кнопка закрытия |

Срок ожидания второй клавиши: **1,8 секунды**. Неподходящая следующая клавиша сбрасывает последовательность без перехода. Переход обновляет настоящий `location.hash`, поэтому работают Back/Forward и копирование адреса. Клавиши `G` и `?` можно отключить в справке; настройка сохраняется в браузере. Даже после выключения кнопка справки и ссылки остаются доступными.

Эта таблица — реальный контракт **конкретной витрины**, а не жёсткий набор клавиш для всех продуктов. Остальные приложения выбирают свой список, соблюдая общие правила.

## Как оформлять подсказки

- **Для команды**: сначала понятная подпись — «Открыть поиск», «К компонентам», «Закрыть панель». Справа — небольшое `ShortcutKeys`; не пиши отдельную документацию прямо на кнопке.
- **Сочетание** (одновременное нажатие): `<ShortcutKeys keys={["⌘","K"]} mode="combo"/>`. **Последовательность**: `<ShortcutKeys keys={["G","C"]}/>`. Не показывай их одинаково: для последовательности используется стрелка `→`, для одновременного нажатия — `+`.
- **Типографика:** знак клавиши — `--font-mono` (JetBrains Mono), обычные подписи — `--font-sans` (Manrope). Без кастомной гарнитуры, металлического объёма, сильной тени и цветного градиента.
- **Цвет:** `--surface-inset` для площадки, `--border-strong` для тонкой рамки, `--ink-soft` для символа, `--ink-faint` для разделителя. Акцент `--accent` допустим только для активной/подсвеченной команды, а не для всей таблицы.
- **Форма:** малый радиус `--radius-xs`, равные отступы, без ощущения кликабельной кнопки. Сам `kbd` семантически обозначает клавишу и **не получает** `onClick`.
- **Текст для скринридера:** полная последовательность читается как «G, затем I»; для аккорда — «⌘ плюс K». Разделители `+` и `→` декоративны.
- **Справка:** обычная кнопка с доступным именем «Горячие клавиши» (на витрине — иконка клавиатуры, подпись «Клавиши» и небольшой `?`-hint) открывает существующий `InspectDrawer`. В нём есть список, ссылки, переключатель включения и описание ограничений. Не создавать конкурирующую панель или автоматический popup.
- **В тёмной теме** не вводи другую палитру: подсказки используют те же семантические токены. Проверяй контраст, фокус, читаемость и `prefers-reduced-motion`.

## Расположение помощи — зависит от продукта

- **Sidebar-приложение:** помощь и шорткаты уместны в нижней утилитарной секции боковой панели (подход Linear), без нового элемента среди основных направлений.
- **Редактор или канвас:** допустима тихая кнопка в нижнем углу (Figma и Notion используют нижний правый). Нужны safe-area, focus-visible, 44px touch target и отсутствие перекрытия реальных действий.
- **Документация и лонгрид:** если помощь почти никогда не нужна, хватит ссылки в футере и реального `?`. Для витрины Vanya UI выбран компактный нижний левый угол, освобождающий шапку для исходников и темы; это локальное продуктовое решение, не новый обязательный UI-примитив.
- **Контекстная подсказка важнее списка:** показывайте сочетание рядом с выполняемым действием или в командном меню. Не используйте навязчивые auto-toast и popover при прокрутке.
- **Реальная доступность:** помощь открывается мышью/касанием/Tab/Enter и `?` (если он включён). При отключении символьных shortcuts кнопка остаётся доступной согласно WCAG 2.1.4.

Исследование с первоисточниками и критериями выбора: [Расположение помощи и discoverability](../research/keyboard-help-placement-2026-11-22.md).

## Контрольный список перед релизом

- [ ] Все команды имеют доступный путь без горячей клавиши.
- [ ] Браузерные и системные сочетания не перехватываются; `metaKey`, `ctrlKey`, `altKey` игнорируются, кроме явно разрешённых и проверенных команд.
- [ ] Ввод текста, композиция IME, повторы клавиши и чужие открытые диалоги не вызывают глобальные действия.
- [ ] Не существует двух команд с одним сочетанием в одном контексте.
- [ ] Справка соответствует реализованным командам (один источник данных).
- [ ] Буквенные сочетания отключаются; настройка работает после перезагрузки.
- [ ] Действия изменяют URL только при настоящем переходе, не через фиктивный `setState`.
- [ ] Тесты проверяют клавиатуру, фокус, сценарии ввода, выключение, Back/Forward, light/dark и мобильную версию.
- [ ] Подсказки не зависят от цвета и не выглядят как отдельные кнопки.

## Исследование и источники

- [WCAG 2.2 SC 2.1.4: Character Key Shortcuts](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html): обязательный выключатель/переназначение/ограничение по фокусу.
- [Apple HIG: Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards/): сохраняй знакомые системные команды, помогай обнаруживать свои.
- [Apple HIG: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/): не переопределяй клавиши системы; проверяй доступ с клавиатуры.
- [GitHub Keyboard Shortcuts](https://docs.github.com/en/get-started/accessibility/keyboard-shortcuts): примеры последовательностей `G` → `C`, списка команд и настройки.
- [MDN: KeyboardEvent.key](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/key) и [KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code): символ и физическая клавиша — не одно и то же.
