# Тексты Vanya Arc / UI: правила и скиллы

Публичный [раздел «Тексты»](https://ui.vanya-arc.dev/#writing). Проектная редакционная политика: [`.agents/redpolitika.md`](../../.agents/redpolitika.md).

## Читатель и задача

Читатель — дизайнер, разработчик или агент, изучающий React-компоненты. После чтения он должен понять, **что это**, **что можно попробовать** и **как подключить**. На первом экране доступны реальные действия: открыть событие, посмотреть подробности, сдвинуть точки ползунком, сменить тему, перейти к каталогу.

## Правила

1. Сначала пользовательский сценарий и проверяемые факты, затем заголовок.
2. В заголовке называй предмет: «Готовые компоненты для рабочих интерфейсов». Под ним — проверяемый способ попробовать.
3. Кнопка называет действие: «Открыть детали», «Перейти к компонентам». Не пиши «ОК», когда доступно содержательное название.
4. Не выдумывай метрики, результаты, отзывы, гарантии, аудиторию и сроки.
5. Оставляй детали по запросу: абзац вводит в задачу, отдельная панель объясняет условия.
6. Говори спокойно и прямо. На витрине можно обращаться на «ты»; в справочнике — нейтральный профессиональный регистр.
7. Убирай неопределённость, канцеляризмы и чрезмерные обещания. Не превращай сокращение в цепочку рубленых предложений.
8. Проверяй генеративные клише: «не просто X, а Y», абстрактную «революционность», бессодержательные тройки выгод.
9. В ошибках и пустых состояниях указывай событие и доступный следующий шаг. Не обвиняй пользователя.
10. Проверяй ссылку в браузере: текст действия обязан соответствовать реальному поведению.

## Рабочий процесс для агента

1. Прочитай `.agents/redpolitika.md` — проектный словарь и фактуру.
2. Сверь задачу и действие с настоящими компонентами `src/showcase` и `src/components`.
3. Для первого экрана применяй `promo`, для команды — `ux-copy`, для финальной правки — `redaktura`.
4. Отмечай неустановленные факты; не дописывай их как доказанные.
5. Сохрани разбор «было / стало / почему» в отдельный документ исследования.
6. Проверь итоговый текст в UI, документации и Markdown для агентов.

## Разбор первого экрана

- **Было:** «Компоненты, которые не заслоняют главное.» Фраза не называет тип продукта; «главное» не определено.
- **Стало:** «Готовые компоненты для рабочих интерфейсов.» Следом — действия с точкой, боковой панелью, ползунком и темой. Категория названа; действие проверяется кодом.
